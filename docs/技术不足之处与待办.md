## 一、技术不足之处（按优先级）

### ✅ P0 · AI 功能每日额度限制（已实现）

- **已实现**：AI 相关接口（AI 导师 `/api/tutor/chat`、能力分析 `/api/assessment/analyze`、课程推荐 `/api/recommend/courses`、实操分析 `/api/practice/analyze`）现已接入鉴权 + 每日额度限流。
- **规则**（`backend/services/ai_quota.py`）：
  - 匿名用户：不计数不限流（保持匿名测评语义）。
  - 已缴押金用户（含退费流程中/续学）：不限。
  - 未缴押金登录用户（含试用期）：今日所有 AI 功能总调用数 ≥ `AI_DAILY_LIMIT_DEFAULT`（默认 **20 次/天**）时返回 429 `ai_quota_exceeded`。
- **配置**：`AI_DAILY_LIMIT_DEFAULT`、`AI_FEATURES`（tutor/assessment/recommend/practice）在 `config.py`，可环境变量覆盖。

### ✅ P1 · 运营后台覆盖：视频 / 项目 / 学习路径全改数据库驱动（已实现）

- **已实现**：`videos`、`projects`、`learning_paths` 三个模块的后端读取逻辑均已从 JSON 文件改为读数据库表，后台管理改动**即时前端生效**。
- 学习路径的动态生成（方向蓝图）已收敛到 `database.py` 种子阶段，运行时仅保留推荐方向排序 + per-user 进度合并 + 章节自动完成 + 顺序解锁。

### ✅ P1 · 后台"作业复核 / 退费复核"页面加载失败（已修复）

- **根因**：页面请求 URL 双重拼接 `/api/admin` 前缀（前端已带 `/api/admin`，再拼一次导致 404）。
- **已修复**：`admin_panel.html` 中作业/退费复核的 `api()` 调用路径纠正，页面现可正常加载。

### ✅ P2 · 后台"用户权限 / 试用管理"（已实现）

- **已实现**（`admin.py` + `admin_panel.html`）：后台新增「用户权限」模块，可对指定用户：
  - 查看试用状态（试用中 / 将到期 / 已锁定 / 后台解锁）、押金状态；
  - `reset_trial`（重置试用起点）、`extend_trial`（延长试用天数）、`clear_trial`（清空起点）；
  - `set_override`（人工强制锁定/解锁）、`clear_override`（清除人工覆盖恢复派生）。
- 替代了之前"调过期要直接改数据库"的操作方式。

## 二、运营后台现状

- **入口**：`/admin`（后端 FastAPI 托管单页 HTML）
- **登录**：管理员账号（`admin_users` 表校验，HMAC/SHA256）
- **已实现的功能**：
  1. **数据看板**：用户总数、押金报名、已退费、累计打卡、社区帖子/回复、视频观看、测评次数、FAQ 条目、学习小组、平均测评分、测评等级分布
  2. **作业复核**：列出作业提交，AI 评分 + 人工改判（通过/未通过）
  3. **退费复核**：达标学员退费申请入队，人工放行/驳回（防刷闭环）
  4. **用户权限 / 试用管理**：查看用户试用状态/押金状态，重置/延长/清空试用起点，人工锁定/解锁（替代直接改库）
  5. **通用表管理**：按导航分组（首页内容 / 课程内容 / 用户体系 / 答疑管理 / 平台运营），对每张表做增删改查、搜索、JSON 字段编辑、启停开关
- **技术形态**：`backend/routers/admin_panel.html`（单页前端，原生 JS）+ `backend/routers/admin.py`（通用 CRUD + 看板 + 复核 + 权限接口）

## 三、后台已存在的硬编码（记录，待后续清理）

> 这些都是写死在前端页面或后端配置里的，改配置/业务时容易漏改。

1. **登录框预填账号密码**（`admin_panel.html:110-114`）：`value="admin"` 和 `value="admin123"` 写死 → 默认凭据暴露在页面源码里。
2. **字段中文映射** `FIELD_LABELS`（`admin_panel.html:155-179`）：所有表字段的中文名写死在前端，新增字段需手动补。
3. **导航分组** `GROUP_MAP` / `GROUP_ORDER`（`admin_panel.html:182-190`）：哪些表进哪个分组、"数据看板/复核"等菜单写死。
4. **JSON 字段名单** `isJsonField`（`admin_panel.html:455-459`）：哪些字段按 JSON 编辑，写死列表。
5. **自动字段** `AUTO_FIELDS = ['id','created_at','updated_at']`（`admin_panel.html:453`）：新增/编辑时排除，写死。
6. **作业阶段名** `stageName = {1:...7:...}`（`admin_panel.html:348`）：七阶段中文名写死。
7. **数据看板指标卡**（`admin_panel.html:311-316`）：看板展示哪些数字、叫什么，写死。
8. **后端表配置** `TABLE_CONFIG`（`admin.py:57-80`）：每张表的字段白名单、标签写死在后端。

> 硬编码本身不算 bug，但会造成"改业务时两边不同步"。建议后续把字段映射、分组、表配置统一收口（比如从数据库/配置文件读取），属可优化项，非阻塞。
