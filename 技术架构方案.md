### 1.2 分层设计原则

| 层级 | 职责 | 关键原则 |
|---|---|---|
| **客户端** | UI 渲染、用户交互、本地缓存 | 不包含业务逻辑，仅做数据展示与用户输入 |
| **API 网关** | 统一入口、鉴权、限流、日志 | 无状态，所有请求经过网关 |
| **业务服务** | 核心业务逻辑 | 服务间解耦，通过 API 或消息队列通信 |
| **AI 服务** | AI 能力封装 | 独立部署，可横向扩展 |
| **LLM 网关** | 多模型统一调度 | 屏蔽底层模型差异，支持动态切换 |
| **数据层** | 持久化存储与缓存 | 读写分离，核心数据多副本 |

## 4. AI 服务层详细设计

### 4.1 LLM 网关设计

LLM 网关的核心职责是**屏蔽底层模型差异，提供统一的调用接口，支持动态路由和降级**。

```python
# 网关核心接口设计（伪代码）
class LLMGateway:
    """多模型统一调度网关"""

    def __init__(self):
        self.providers = {
            "deepseek-coder": DeepSeekProvider(),
            "gpt-4o-mini": OpenAIProvider(),
            "claude-3.5": AnthropicProvider(),
            "qwen-coder": QwenProvider(),
        }

    async def chat(
        self,
        messages: List[Message],
        scene: str,           # 调用场景：assessment / qa / code_review / job_match
        stream: bool = False,
        fallback: bool = True # 是否允许降级
    ) -> ChatResponse:
        # 1. 根据场景选择最优模型
        provider = self.route(scene)

        # 2. 注入场景专属 System Prompt
        messages = self.inject_system_prompt(messages, scene)

        # 3. 调用模型，失败时降级
        try:
            return await provider.chat(messages, stream)
        except Exception:
            if fallback:
                fallback_provider = self.get_fallback(scene)
                return await fallback_provider.chat(messages, stream)
            raise
```

**场景路由策略：**

| 调用场景 | 首选模型 | 降级模型 | 路由原因 |
|---|---|---|---|
| 能力测评 | GPT-4o mini | Qwen Coder | 需要结构化输出，mini 性价比高 |
| 学习路径生成 | Claude 3.5 | GPT-4o mini | 长上下文，需理解复杂逻辑 |
| AI 答疑 | Claude 3.5 | DeepSeek Coder | 长上下文，解释清晰 |
| 代码批改 | DeepSeek Coder | GPT-4o mini | 代码能力强，成本低 |
| 岗位对标 | GPT-4o mini | Qwen Coder | 结构化输出，解析 JD |
| 题目生成 | DeepSeek Coder | GPT-4o mini | 代码生成强，成本低 |

### 4.2 能力测评引擎

**流程：**

```
用户开始测评
    ↓
1. 基础信息收集（专业、年级、目标方向）
    ↓
2. 自适应出题（根据前面回答调整难度）
    ├── 编程基础题（Python 语法、数据结构）
    ├── 数学基础题（线代、概率统计）
    ├── AI 认知题（ML/DL 基础概念）
    └── 场景题（根据目标方向动态生成）
    ↓
3. 答案收集 → LLM 批量评分
    ↓
4. 生成能力雷达图 + 水平报告 + 学习建议
    ↓
5. 推荐学习方向 + 起点
```

**核心数据模型：**

```python
class AssessmentResult(BaseModel):
    """测评结果"""
    dimensions: Dict[str, float]  # 维度得分 {"python": 75, "math": 60, "ml": 40}
    level: str                     # 综合等级：beginner / intermediate / advanced
    strengths: List[str]           # 优势
    weaknesses: List[str]          # 薄弱点
    recommended_paths: List[Path]  # 推荐学习路径
    estimated_time: int            # 预估学习时长（小时）
```

### 4.3 学习路径生成器

**核心逻辑：**

1. 输入：测评结果 + 目标方向 + 每周可用时间
2. 从课程知识图谱中匹配节点
3. 按依赖关系排序，生成周计划
4. 动态调整：根据学习进度和练习正确率，调整后续路径

**知识图谱结构（简化）：**

```
Python 基础 → 数据分析 → 机器学习 → 深度学习 → 大模型应用
    ↓            ↓          ↓           ↓           ↓
  [必学]      [必学]     [选学]      [选学]      [高阶]

AI 产品思维 → Prompt Eng → AI 工具链 → AI 产品设计 → 项目实战
    ↓            ↓           ↓           ↓           ↓
  [必学]      [必学]     [必学]      [必学]      [核心]
```

### 4.4 AI 答疑引擎

**设计思路：** 不是通用 AI，而是**绑定当前学习上下文的智能答疑**。

```python
class QAEngine:
    """AI 答疑引擎"""

    def build_context(
        self,
        user_id: str,
        course_id: str,
        current_chapter: str,
        learning_history: List[Progress]
    ) -> str:
        """
        构建答疑上下文，包含：
        1. 当前课程内容和章节
        2. 用户已学知识点
        3. 用户薄弱点（来自测评）
        4. 用户之前的提问历史
        """
        # 拼装为 System Prompt
        return f"""
        你是一个 AI 编程导师，正在辅导一位学生学习 {course_name}。
        当前章节：{current_chapter}
        学生已掌握：{mastered_topics}
        学生薄弱点：{weak_topics}
        回答要求：
        - 解释要结合课程内容，不要超出学生当前水平过多
        - 不要直接给答案，先引导思考
        - 可以给出代码示例，但要解释每一行
        """
```

### 4.5 代码批改引擎

**设计思路：** 不只判断对错，而是**指出问题 + 给出改进方向 + 参考运行结果**。

```python
class CodeReviewEngine:
    """代码批改引擎"""

    async def review(
        self,
        code: str,
        project_id: str,
        step_id: str,
        language: str = "python"
    ) -> CodeReviewResult:
        """
        批改流程：
        1. 静态检查：语法、风格、常见错误
        2. 逻辑检查：是否满足项目步骤要求
        3. 运行检查（可选）：沙箱执行代码
        4. 改进建议：代码优化、最佳实践
        """
        prompt = f"""
        作为代码审查者，请检查以下 {language} 代码。

        项目要求：{step_requirements}
        评分标准：{rubric}

        请按以下格式输出：
        1. 评分：[0-100分]
        2. 功能正确性：[通过/不通过] - 具体问题
        3. 代码质量：[好/中/差] - 具体问题
        4. 优化建议：[3-5条具体建议]
        5. 知识点总结：[本次练习涉及的知识点]
        """
        response = await self.gateway.chat(prompt, scene="code_review")
        return self.parse_review(response)

class CodeReviewResult(BaseModel):
    score: int
    passed: bool
    issues: List[CodeIssue]
    suggestions: List[str]
    knowledge_points: List[str]
```

### 4.6 岗位对标引擎

**设计思路：** 解析岗位 JD → 提取能力要求 → 与用户能力对比 → 生成差距报告。

```python
class JobMatcher:
    """岗位能力对标引擎"""

    async def match(
        self,
        user_id: str,
        job_description: str
    ) -> MatchResult:
        """
        对标流程：
        1. LLM 解析 JD，提取结构化能力要求
        2. 从数据库读取用户能力画像
        3. 逐项对比，计算匹配度
        4. 生成差距报告 + 补齐建议
        """
        # Step 1: 解析 JD
        requirements = await self.parse_jd(job_description)

        # Step 2: 获取用户能力
        user_skills = await self.get_user_skills(user_id)

        # Step 3: 对比
        gaps = []
        for req in requirements:
            user_level = user_skills.get(req.skill, 0)
            if user_level < req.required_level:
                gaps.append(SkillGap(
                    skill=req.skill,
                    current=user_level,
                    required=req.required_level,
                    courses=await self.find_courses(req.skill),
                    projects=await self.find_projects(req.skill)
                ))

        return MatchResult(
            match_score=calculate_match(requirements, user_skills),
            gaps=gaps,
            recommend_courses=get_recommendations(gaps),
            recommended_projects=get_project_recommendations(gaps)
        )
```

## 7. 安全设计

### 7.1 认证与鉴权

- **微信登录：** 小程序端调用 `wx.login()` 获取 code → 后端换 openid → 生成 JWT
- **JWT Token：** access_token（2 小时）+ refresh_token（7 天）
- **Token 刷新：** 前端拦截器自动刷新，用户无感
- **API 鉴权：** 所有业务 API 需携带 Authorization Header

### 7.2 数据安全

| 措施 | 说明 |
|---|---|
| 传输加密 | 全站 HTTPS，API 强制 TLS 1.2+ |
| 敏感数据加密 | 手机号、邮箱 AES-256 加密存储 |
| 代码隔离 | 用户提交代码在沙箱环境执行，限制网络和文件系统 |
| SQL 注入防护 | ORM 参数化查询，禁止拼接 SQL |
| XSS 防护 | 输入输出严格过滤，CSP 头配置 |

### 7.3 接口安全

| 措施 | 说明 |
|---|---|
| 请求签名 | 关键接口（支付、订单）增加请求签名校验 |
| 频率限制 | 同一用户/IP 限制请求频率（如 100次/分钟） |
| 幂等性 | 支付、订单创建接口保证幂等，防止重复提交 |
| 参数校验 | Pydantic 严格校验所有输入参数 |
